# Contributing to Design Review

First of all — thank you for considering contributing!

This project exists to help freelancers deal with messy design feedback. Every contribution, big or small, helps.

## Ways You Can Contribute

- Report bugs
- Suggest new features
- Improve UI / UX
- Fix documentation
- Write tests
- Improve accessibility
- Help with translations (future)

## Getting Started

1. Fork the repository
2. Clone your fork:
   ```bash
   git clone https://github.com/YOUR_USERNAME/Design-Review.git
   ```
3. Create a new branch:
   ```bash
   git checkout -b feature/your-feature-name
   ```
4. Make your changes
5. Commit with a clear message
6. Push and open a Pull Request

## Good First Issues

Look for issues labeled `good first issue`. These are intentionally small and well-scoped so new contributors can get started easily.

## Code Guidelines

- Use TypeScript
- Follow the existing code style
- Prefer clear and readable code over clever code
- Keep components relatively small
- Write meaningful commit messages

## Pull Request Process

1. Make sure your code runs without errors
2. Describe what you changed and why
3. Link any related issues
4. Be open to feedback — we review every PR

## Feature Requests & Ideas

Have an idea?  
Please open a [GitHub Discussion](https://github.com/nareshbabunuli/Design-Review/discussions) or create an issue with the label `feature request`.

We love hearing from people who actually use this tool with real clients.

## Code of Conduct

Be respectful, constructive, and kind. We’re all here to build something useful together.

Thank you for helping make Design Review better 🙌
